# قواعد معمارية المشروع (Architecture Rules)

## 1. حد حجم الملفات (File Size Limit)
- **ممنوع نهائياً أن يتجاوز أي ملف في المشروع حاجز الـ 200 سطر.**
- إذا قارب أي ملف على الوصول إلى 200 سطر، يجب تجزئته ونقله إلى مجلد فرعي متخصص.

## 2. مبدأ المسؤولية الواحدة (Single Responsibility Principle)
- كل ملف يجب أن يؤدي مهمة واحدة محددة وواضحة (مثل: دوال التواريخ، نوافذ الحوار، أدوات المعاملات المالية).
- يُمنع دمج مهام غير مرتبطة في نفس الملف.

## 3. بساطة الكود وقابلية التوسع (Simplicity & Scalability)
- الكود يعتمد على Vanilla JavaScript (ES6) واضح ونظيف بدون تعقيد أو مكتبات زائدة.
- يتم تنظيم الملفات داخل مجلدات منطقية تعكس بنيتها الوظيفية.

## 4. الحفاظ على العقود الأساسية (Core Integrity)
- عند تفكيك أي ملف، يجب الحفاظ على الواجهات العامة وتصدير الدوال والمتغيرات إلى `window` حتى تظل بقية أجزاء التطبيق والاختبارات تعمل بسلاسة تامة.
